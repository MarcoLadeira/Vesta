How Vesta works

One routing ladder, run on every task:

deterministic tools → compact cache/context → local model → confirmed cheap cloud → strong model only after evidence

1

Vesta gathers evidence

It scans your repo, runs your tests, and checks the git diff. No guesswork, no blind model calls — routing starts from facts on disk.

opai doctor
$ opai doctor
Vesta 0.2.0 alpha.2 — readiness check
✓ clients      claude · codex · copilot · cursor · cline
✓ python       3.12.3 (>=3.10)
✓ registries   tools · cache · models
✓ stale paths  none
2

Routes intelligently

A lint fix goes to a local tool like ruff or eslint. A test debug goes to local evidence plus a cheap model. Design and architecture go to a strong model — only with your confirmation.

opai route
$ opai route "clean up lint in src/api"
→ evidence   ruff check: 6 violations in 2 files
→ context    48,200 → 3,100 tokens
→ decision   local tool: ruff --fix
→ cost       $0.00 · cloud call: no
3

Proves savings

opai savings shows exactly what you avoided. Every. Single. Time.

opai savings
$ opai savings --markdown
| tasks routed locally | 41      |
| tokens avoided       | 182,400 |
| estimated saved      | $6.31   |
| cloud calls made     | 0       |
Paid and cloud calls are never counted as savings.
