# Vesta QA — objective-based completion verdicts (#378)

## Contract

Every terminal response carries `completion_verdict` with a stable verdict,
machine-readable `reason_code`, human reason, objective acceptance, observed
evidence references, and a safe next action. The GUI, streaming CLI, workflow
state, checkpoint, task-outcome ledger, and per-turn receipt consume that one
result. Compatibility `status` remains available to old callers, but cannot
upgrade a non-`completed` verdict.

Raw objective text is available only in the live response. Persisted workflow,
checkpoint, ledger, and receipt forms retain the acceptance contract and
evidence but omit the prompt text.

## Hermetic regression matrix

| Fixture | Required evidence | Expected verdict | Reason code | Surface assertion |
| --- | --- | --- | --- | --- |
| Edit plus passing test | changed file + successful `run_tests` | `completed` | `objective_verified` | GUI/receipt/workflow agree |
| Edit without required test | changed file only | `partial` | `tests_not_verified` | CLI exits 2; UI is amber, never green |
| Capability mismatch | typed mismatch result | `blocked` | `capability_mismatch` | next action names a capable provider |
| User cancellation | cancellation signal | `cancelled` | `cancel_requested` | CLI exits 130; no success style |
| Runner timeout | typed timeout | `timeout` | `timeout` | GUI/CLI show timeout, not generic failure |
| Provider crash | typed/legacy failure | `failed` | `provider_failed` | no completed label or receipt success claim |

## Regression invariant

No renderer may use an answer string, a legacy `answered` status, or provider
prose as evidence of success. Only `completion_verdict.verdict == "completed"`
may show the green completion treatment or return CLI exit code 0.
